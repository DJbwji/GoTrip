# GoTrip
**Твои люди. Твои места. Твоё путешествие.**

Многостраничная туристическая платформа на Python и Django 5.2: экскурсии, гиды, бронирования и поиск попутчиков. Интерфейс реализован Django Templates, CSS и JavaScript по композиции предоставленного референса: побережье на первом экране, светлая палитра, оранжевые акценты, направления, сообщество и карточки поездок. Фотографии и шрифты хранятся локально.

## Быстрый запуск
Требуется Python 3.10+ (проект проверен на Python 3.12).

Windows PowerShell:
```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe manage.py migrate
.venv/Scripts/python.exe manage.py seed_demo
.venv/Scripts/python.exe manage.py runserver
```

Если окружение уже подготовлено в этой папке:
```powershell
.venv/Scripts/python.exe manage.py runserver
```
Или запустите `start.ps1`. Откройте http://127.0.0.1:8000/ . Остановка сервера — Ctrl+C.

Linux/macOS: вместо `.venv/Scripts/python.exe` используйте `.venv/bin/python`.

## Демонстрационные аккаунты
Команда `seed_demo` создаёт аккаунты только при DEBUG=True. Повторный запуск не сбрасывает пароли и не дублирует основные объекты.

| Роль | Email | Пароль |
|---|---|---|
| Турист | tourist@gotrip.local | GoTrip2026! |
| Гид | guide@gotrip.local | GoTrip2026! |
| Администратор / модератор | admin@gotrip.local | GoTrip2026! |
| Кандидат в гиды | newguide@gotrip.local | GoTrip2026! |

Дополнительные участники: `ivan@gotrip.local`, `marina@gotrip.local`, тот же демонстрационный пароль. Администратор входит также через /admin/; его username совпадает с email.

Демо включает 5 направлений, 12 опубликованных экскурсий, заявку экскурсии на модерации, заявку гида, 4 публичные поездки, оплаченные прошедшие экскурсии, отзывы, жалобу и диалог. Даты вычисляются относительно дня наполнения. Для долгой демонстрации используйте новую SQLite-базу или добавляйте актуальные даты через кабинет гида.

## Что реализовано
- Главная, каталог с поиском, фильтрами (направление, дата, цена, гости, категория), сортировкой и пагинацией.
- Экскурсия с галереей, датами, остатком мест, информацией о гиде, рейтингом и отзывами.
- Регистрация и вход по email, выход только POST, восстановление пароля одноразовой email-ссылкой.
- Личный кабинет: бронирования, избранное, поездки, история, обращения, редактирование профиля и аватара.
- Полный CRUD экскурсий и публичных поездок. Владелец редактирует и удаляет только свои объекты.
- Подача заявки гида, проверка модератором, комментарий, исправление и повторная подача.
- Черновик экскурсии → отправка → обязательная модерация → публикация. При изменении опубликованная экскурсия снова становится черновиком.
- Модератор видит описание, фото, цену, даты и данные гида; принимает решение: одобрить, отклонить или отправить на доработку. Для отклонения/доработки причина обязательна.
- Email-уведомления регистрации, новой заявки, новой жалобы, бронирования и решений. Получатели модерации — активные staff-пользователи и MODERATOR_EMAIL.
- Бронирование с атомарным резервированием мест и расчётом суммы на сервере. Отмена неоплаченной брони освобождает места.
- Отдельный экран демонстрационной оплаты. Повторное подтверждение не изменяет число мест.
- Публичные поездки: организатор, состав, вместимость, вступление и выход.
- Личный диалог туриста с гидом, доступный только двум участникам. Новые сообщения видны после обновления страницы.
- Отзыв 1–5 и жалоба доступны только после даты оплаченной экскурсии. Один отзыв на экскурсию, допускается его обновление.
- Ранги туристов по завершённым оплаченным бронированиям: 0–2 — Первооткрыватель, 3–9 — Исследователь, 10+ — Легенда путешествий. Ранги гидов по опубликованным экскурсиям: 0–2 — Новый гид, 3–9 — Опытный гид, 10+ — Мастер впечатлений.
- Загрузка изображений с Pillow: ограничение 8 МБ, корректировка EXIF-ориентации, уменьшение до 1600×1200.
- AJAX-переключение избранного; без JavaScript работает обычная HTML-форма.
- Все основные модели зарегистрированы в Django Admin с поиском, фильтрами и списками. Чувствительные статусы доступны для просмотра, бизнес-переходы выполняются через кабинеты сайта.

## Структура
| Приложение | Ответственность |
|---|---|
| gotrip | Настройки, корневые URL, WSGI |
| core | Главная, страница проекта, активность, email, обработка фото, демоданные, тесты |
| users | Пользователь, профиль, заявки гидов, email-аутентификация |
| tours | Направления, категории, экскурсии, даты, фото, отзывы, избранное |
| bookings | Бронирование, демонстрационная оплата, отмена |
| trips | Публичные поездки, участники, CRUD |
| messaging | Приватные диалоги туриста с гидом |
| moderation | Кабинет модератора, жалобы, решения |
| templates / static | Наследуемые шаблоны, адаптивные стили, JS, изображения, локальные шрифты |

Связи ForeignKey, ManyToManyField и OneToOneField реализованы. У моделей есть __str__, Meta, verbose_name, ordering и related_name. Миграции включены в проект.

## Настройки
Скопируйте `.env.example` в `.env`. Файл читается автоматически; переменные среды имеют приоритет. Поддерживаются строки KEY=value без интерполяции.

По умолчанию SQLite и Console Email Backend: письма выводятся в терминал сервера, а не отправляются во внешний почтовый ящик. Для SMTP задайте EMAIL_BACKEND, EMAIL_HOST, EMAIL_PORT, EMAIL_HOST_USER, EMAIL_HOST_PASSWORD, DEFAULT_FROM_EMAIL и MODERATOR_EMAIL.

Для PostgreSQL:
```powershell
.venv/Scripts/python.exe -m pip install "psycopg[binary]>=3.2,<4"
```
Затем заполните POSTGRES_* и выполните migrate. PostgreSQL-конфигурация предусмотрена, автоматические проверки выполнены на SQLite.

## Границы демонстрационной версии
Оплата **тестовая**: реальный провайдер, списание денег и возвраты не подключены. DEMO_PAYMENTS=0 отключает подтверждение. Для реального запуска нужны серверная интеграция провайдера, подписанные webhooks, идемпотентность внешних транзакций и возвраты. Неоплаченные брони сохраняют места до ручной отмены владельцем; автоматическое истечение брони пока не реализовано.

runserver предназначен для локального запуска. Перед размещением задайте DJANGO_DEBUG=0, уникальный DJANGO_SECRET_KEY и домены; настройте HTTPS, production WSGI-сервер, раздачу static/media и SMTP. Выполните collectstatic. Не используйте публично тестовые аккаунты и пароли. Резервное копирование БД и медиа организуется на хостинге.
